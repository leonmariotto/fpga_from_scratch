# Chapter 06 : Architecture

This chapter cover the programmer view of a processor: the architecture 
level. *I'm a bit aware of it but I'll follow the chapter, maybe quickly 
on obvious things*. The digital design view of a processor (the arrangement 
of building block such as ALU, registers, etc) is called a *micro-
architecture* and will be cover next chapter.

RISC-V architecture has been defined in 2010 in Berkeley, California. RISCV is 
unusual in that its open-source nature make it free to use, and is comparable 
(for low end device at least) to commercial architecure such as ARM. We're 
gonna describe and implement RV32I variant, it's the base 32-bit ISA, 
barely usable for a concrete application.

Many extension exist: Multiply and Divide, CSR (Control Status Register), 
Floating point, instruction-fetch synchronization, bit manipulation ... 
Everything is an extension, even the most basic stuff, the idea is to be able 
to design something that fit exactly your need.

4 principles motivate RISCV design : (1) regularity supports simplicity, (2) 
make the common case fast, (3) smaller is faster, (4) good design demands 
good compromises.

RISCV 32 registers set :

| Name  | Nb     | Use                                           |
|-------|--------|-----------------------------------------------|
| zero  | x0     | Constant value 0.                             |
|  ra   | x1     | Return address.                               |
|  sp   | x2     | Stack pointer.                                |
|  gp   | x3     | Global pointer.                               |
|  tp   | x4     | Thread pointer.                               |
| t0-2  | x5-7   | Temporary registers.                          |
| s0/fp | x8     | Saved register/Frame Pointer.                 |
|  s1   | x9     | Saved register.                               |
| a0-1  | x10-11 | Function argument/Return value.               |
| a2-7  | x12-17 | Function arguments.                           |
| s2-11 | x18-27 | Saved registers.                              |
| t3-6  | x28-31 | Temporary registers.                          |

RISCV instruction can do *register operation* but also use *imediate operands*. 
RV32I use 32 bit address and 32 bit data word for memory access with `lw` or 
`sw` instructions.

Control flow use usual instructions (same as ARM).

Function call is done through `jal` Jump-and-link instruction, `jr` Jump 
register is used to return. Inputs are `a0-7`, `s0-11` are callee-saved 
register (preserved), they will not be written by callee, `t0-6` and `a0-7` may 
be used by callee.

4 instructions format:
- *R-type*: operate on 3 registers. 2 sources and 1 destination.
- *I-type*: Operate on 2 register and a 12 bit imediate value.
- *S/B-type*: store/branch instruction. Operate on 2 register and a 12 or 13 
bit imediate value.
- *U/J-type*: upper immediate/jump. Operate on 1 register and 20 or 21 bits 
immediate value.

RISCV try to keep immediate value at the same place accross instruction format, 
it simplify hardware design at the cost of instruction encoding complexity.

RISCV, like almost all architecture, use the following addressing scheme:
- Register-only addressing: register only for source and destination.
- Immediate addressing: use the raw immediate value (`addi`, `slli`, ...)
- Base addressing: the effective address is calculed by adding the base 
address to the signed immediate operande. (`lw`, `sw`, `sb`, ...)
- PC-relative addressing: the signed immediate value is added to the PC 
register to compute the address. (`jal`, ...)

REV32I don't include CSU, so we need special instruction `csrr` to access 
values of exception handling: `mtvec`, `mcause`, `mepc`, ... Theses instruction 
are part of REV32I.

RISCV is very similar to MIPS. Also, but less, to ARM. ARM include some 
(small) features of MIPS processor, *conditional execution*, *shifted 
register*, *indexing mode*, reducing the size of programs, critical in 
embedded system. This, however, comes with more complexity and more hardware.
